# 0001 — 账号凭据同时支持密码续期与 Cookie

状态：已接受
日期：2026-11-08

## 背景

77625路由站的签到和积分只能通过账号会话（Cookie）读取，聊天则需要独立的 API Key。会话会过期；如果只保存 Cookie，签到会在过期后中断；如果只保存密码，不愿把密码交给 Magpie 的用户无法使用。

## 决策

提供两条账号登录路径：

1. **账号密码**：登录后把用户名和密码保存在 `plugin-auth.json`（0600），密码放在账号的 `refresh` 字段，由 Magpie 的 `auth.refresh` 在会话临近过期时自动重新登录。
2. **浏览器会话 Cookie**：只保存 Cookie，不保存密码；会话失效时由 `auth.usage`/`auth.checkin` 抛 `signIn: "expired"`，用户重新登录。

另提供一条 `仅 API Key` 路径，明确标注不能签到/查积分。

## 后果

- 密码方式长期无人值守，适合“自动签到”；代价是密码落在 Magpie 配置里，依赖文件权限与本机安全。
- Cookie 方式更保守，但需要用户周期性重新登录。
- 两条路径都在账号作用域内保存，支持多账号；API Key 的创建/复用逻辑一致。
- 登录失败有本地 5 分钟退避，避免触发站点 429；并发刷新去重。

## 备选方案

- 只保存密码：对安全敏感用户不可接受。
- 只保存 Cookie：无法满足长期自动签到。
- 只提供 API Key：无法签到或查询积分。
