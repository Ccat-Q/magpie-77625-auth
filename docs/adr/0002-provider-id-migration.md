# 0002 — 分阶段接管 provider id 77625

状态：已接受
日期：2026-11-08

## 背景

生产 Magpie 里已经有一个手工配置的 provider `77625`，自动组 `auto-deepseek-v4-1-flash` 和 agent 都引用 `77625/x-deepseek-v4.1-flash`。插件必须声明 `auth.provider = "77625"` 才能让这些引用最终继续有效。但 Magpie 在 id 冲突时会把插件显示为 `77625-plugin`。

## 决策

插件固定声明 `77625`，不选独立 id。迁移分阶段：

1. 安装插件，先以 `77625-plugin` 与手工 provider 并存；
2. 登录并验证聊天、积分、签到；
3. 备份配置后删除手工 provider；
4. 插件宿主重载，插件接管 `77625`；
5. 检查自动组仍包含 `77625/x-deepseek-v4.1-flash`，缺失则按原顺序补回；
6. 验证 agent 引用无需修改。

## 后果

- 迁移前有两个 provider 行，需要用户明确知道用哪个；README 写清步骤。
- 迁移后可保留所有 `77625/...` 引用，减少 agent 配置改动。
- 删除手工 provider 是有副作用的操作，必须先备份并确认插件可用；回滚依靠配置备份。
- 如果用户不想动生产配置，也可长期停留在 `77625-plugin`，但 agent 引用需要改。

## 备选方案

- 使用独立 id（如 `ly77625`）：不冲突，但所有引用都要改，且与“接管 77625”的目标不符。
- 长期并存：最安全，但两套 provider 容易混淆，组仍指向手工 provider。
